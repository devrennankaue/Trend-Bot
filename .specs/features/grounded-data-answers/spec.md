# Grounded Data Answers Specification

## Problem Statement

The assistant currently sends every question through semantic retrieval and generation. This cannot reliably answer database facts such as counts, rankings, and filtered records, and it provides no source evidence for generated claims. The feature adds deterministic local analytics for supported data questions and strengthens the RAG fallback with thresholding, evidence, and document diversity.

## Goals

- [ ] Answer supported factual questions from the local CSV with deterministic calculations and named evidence.
- [ ] Make RAG answers cite retrieved video metadata and abstain when no retrieval score meets the configured threshold.
- [ ] Index all rows by default while retaining an explicit development limit and a safe explicit reindex command.
- [ ] Add regression tests for analytics, retrieval grounding, and conversation routing.

## Out of Scope

| Feature | Reason |
| --- | --- |
| Fine-tuning an LLM | Retrieval and deterministic data access must be reliable first. |
| Remote LLMs, databases, or APIs | The project remains local-first under AD-001 and AD-002. |
| Natural-language SQL generated by an LLM | It permits unsafe or unverifiable queries; supported analytics intents are deterministic. |
| Real-time trend growth calculation | The source does not define a stable historical snapshot contract. |

## User Stories

### P1: Deterministic Database Answers ⭐ MVP

**User Story**: As a TikTok analyst, I want direct questions about indexed data answered from calculated local results so that counts and rankings are trustworthy.

**Why P1**: Direct factual answers are the primary reason to specialize the assistant.

**Acceptance Criteria**:

1. WHEN a user asks for the number of videos THEN the system SHALL return the exact count from the loaded CSV.
2. WHEN a user asks for the most frequent hashtags, songs, or creators THEN the system SHALL return a descending ranking computed from the corresponding CSV field.
3. IF a supported factual question has no matching usable values THEN the system SHALL state that the corpus has no data for that metric.
4. The system SHALL label deterministic answers as results calculated from the local corpus.

**Independent Test**: Load a fixture CSV and verify exact counts and ordered rankings.

---

### P2: Evidence-Grounded RAG Fallback

**User Story**: As a researcher, I want analytical answers to show their source videos and reject weak retrieval so that I can audit their factual basis.

**Why P2**: Semantic synthesis remains needed for questions that cannot be reduced to a database aggregation.

**Acceptance Criteria**:

1. WHEN semantic retrieval returns documents at or above the relevance threshold THEN the system SHALL provide the LLM with each document's source metadata and retrieve no more than one chunk per video.
2. IF every retrieved document is below the relevance threshold THEN the system SHALL return no context to the LLM and use the configured insufficient-information response.
3. WHEN a RAG answer is generated THEN the system SHALL append a Sources section containing the retrieved video IDs and available metadata.
4. WHERE candidate documents contain both semantic and lexical query matches THEN the system SHALL rank candidates using both signals before selecting context.

**Independent Test**: Use fake scored documents to verify thresholding, one-video diversity, lexical ordering, and rendered sources.

---

### P3: Complete and Reproducible Indexing

**User Story**: As a project maintainer, I want indexing to use the full corpus by default and be explicitly rebuildable so that the vector store represents the intended dataset.

**Why P3**: A sample-sized index produces incomplete answers while appearing ready.

**Acceptance Criteria**:

1. WHEN the vector store is created without a limit THEN the system SHALL pass all CSV rows to ingestion.
2. WHERE an explicit index limit is supplied THEN the system SHALL index no more than that number of rows and report the limit.
3. WHEN the CLI receives the `--reindex` option THEN the system SHALL rebuild the local vector store only after displaying the target directory and requiring confirmation.

**Independent Test**: Verify the ingestion limit passed by the CLI and verify that a declined rebuild leaves the vector store untouched.

---

## Edge Cases

- IF the CSV is unavailable when analytics is requested THEN the system SHALL continue with RAG and report that deterministic analytics is unavailable.
- IF a question is not a supported factual intent THEN the system SHALL use the grounded RAG fallback.
- IF source metadata is blank THEN the system SHALL omit that field rather than render a placeholder value.

- [ ] Unsupported or weakly retrieved questions do not produce ungrounded factual output.
